# TECH Tweaks

服务于 TECH 的 Minecraft 26.2 / NeoForge 26.2.0.88 扩展模组。当前双端构建 0.1.9，客户端和服务端都需要安装；服务端模块为 0.1.4，仅服务器安装。0.1.9 已于 2026-10-25 部署 TECH 正式服及客户端两条更新通道；各版本验证记录按日期保留。

## 模块划分与在线备份

同一仓库构建两个 JAR：

- `tech-tweaks-0.1.9.jar`：原有方块、物品、控制器、GUI、网络同步与玩法兼容，双端安装。
- `tech-tweaks-server-0.1.4.jar`：Pipez 搬运优化、压裂塔地表查询、异常落叶清理与在线假人快照，仅服务器安装。不能下发到玩家 AutoModpack 清单。

性能代码及其 Mixin、JUnit 测试已从双端模块迁入 `server/`，算法保持不变；服务端必须配套更新两个 JAR，不能将旧 0.1.3 与服务端模块一起加载，否则会重复应用补丁。

`techbackup snapshot <32位十六进制nonce>` 仅允许最高管理权限，用于运维脚本；在主线程同一命令中捕获当前可驻留假人的原生动作包、强制保存玩家与世界，再原子写入 `world/fake_player.rg.json`。保留 SiliconeDolls 的 `rolling_gate.NoResident` 排除规则，并要求驻留、动作恢复及离线名字生成规则全部开启。空名单也明确写 `{}`，不沿用旧名单。成功回执包含本次 nonce、人数和文件 SHA-256；失败不返回成功回执。

infra-ops 的在线快照脚本负责 `save-off`、调用此命令、校验源文件与复制副本、`save-on` 及 Git LFS 提交。回档后由 SiliconeDolls 原生启动逻辑恢复，恢复工具确认名单内假人已上线后才报告完成。旧快照没有此文件时不能追补当时的名单和动作。

## 0.1.3 性能修复（现归服务端模块）

- Pipez 1.2.32+26.2 物品轮询：只批量执行同一源槽位物品的完整轮次，每个目标获得相同件数。先确认单件抽取／插入仍允许；批量遇到容量不足、过滤拒绝或抽取数量不符时整批回滚，再交回原单件逻辑。混合物品、组件、总速率、余数、目标游标和原有过滤规则保留；不加降频、持久缓存或新升级卡。Pipez 不存在时跳过对应 Mixin。
- NTM 1.0.1 压裂塔地表查询：利用 `WORLD_SURFACE` 高度图直接找到首个非空气方块，替代从世界顶端逐格扫描。保留随机调用、10 列污染处理、产油／耗电／压裂液消耗；高度图包含树冠、水面和屋顶，不缓存过期地表高度。
- HBM 异常落叶：在原版落地处理结束后，仅移除超过 600 tick、已落地静止、`DropItem=false`、无 `TileEntityData` 且仍存活的 `hbm:leaves_layer` 下落实体。活塞占位时保留；不清除正常下落方块、年轻落叶、动物或刷怪设施。
- 管道单件回退路径：同一次搬运中，某种物品被目标明确拒收后，跳过后续槽里完全相同组件的重复探测；抽取失败不计作拒收，下次搬运重新检查。沿用 NeoForge 原事务逻辑，不增加 tick 延迟。
- 管理员 `/tech performance` 查看本进程累计批量次数／件数、跳过的重复拒收探测数、地表查询列数和异常落叶移除数。计数不写入存档。

参考 [Pipez Optimizer](https://www.curseforge.com/minecraft/mc-mods/pipez-optimizer) 的批量均分思路及 [Pipez Lag Fix](https://www.curseforge.com/minecraft/mc-mods/pipez-lag-fix) 的无效工作分析；本实现独立编写，未复制其代码。不要与其他改写 Pipez 搬运算法的补丁同时使用。

控制器合成使用钢板、NTM 电路和红石块。试炼控制器另外需要试炼钥匙，宝库控制器需要漏斗，环境控制器需要时钟，区域抑制控制器需要末影之眼。后两者使用高级电路。每台机器储能上限 1,000,000 FE，电力可由外部 FE 接口输入；NTM 原生供电线路的实际连接仍需验收。

放置时，观察者正面纹理指向目标方块；试炼／宝库目标必须紧邻正面。试炼默认自动运行：每秒检查一次，待上一轮战斗和奖励结算全部完成后扣电启动下一轮，不等待玩家。关闭自动开关只停止新轮，已付费的轮次仍继续正常结算。启用红石控制时只有有信号才自动开新轮；默认不要求红石。忙碌时的脉冲不会排队。宝库默认自动运行，可以在 GUI 启用红石电平控制。多个控制器接入同一目标时只选择一个，避免同时扣材料。

界面同步本轮活怪数量，区分正在刷怪、等待清怪、奖励结算、暂停和缺少能源／瓶子。连续 100 次实际生成尝试失败后提示“刷怪受阻”，成功生成或新轮会清除此提示；不跳过空间、视线、特殊数据包规则，也不把生成失败当作已杀怪。0.1.0 的“运行：开”仅允许手动触发，现有已启用控制器升级后会自动循环并按每轮原有价格消费能源／瓶子。

自动试炼使用一个持久化虚拟参与者驱动原版状态机；不祥模式的原版玩家瞄准攻击仍依赖真实玩家，离线自动轮次不会伪造玩家位置。

## 已确认的饰品栏故障与当前缺口

准确现象：**整个 Curios 饰品栏打不开，背包因此看起来消失；客户端重启、重新登录均无效，只有服务端重启后恢复。** 未确认实际物品存档丢失，根因也尚未复现，因此本版不补发背包、不重建饰品附件、不覆盖玩家存档。

本版提供两项定位／恢复入口：

- `/tech curios inspect`：检查自己的服务端槽位配置、库存附件、可见槽数和装备数，并写入服务器日志。
- `/tech curios resync`：在服务端库存正常时，重新发送已有槽位与物品数据，再尝试打开饰品界面。服务端库存不可用时只报告并记录问题，不修改物品数据。这只能处理同步异常，不能视为根因修复。

正常打开饰品栏的请求也会记录 `[TECH Curios] open` 状态。下次故障应保留故障发生前后的日志，并执行 inspect；需要核对请求是否到达服务端，以及服务端配置／附件是否还在。**饰品栏根因修复未完成。**

简单村民与简单猪灵已由服务器安装的 Easy Villagers / Easy Piglins 提供，不在本模组重复实现。地图共享已按用户要求跳过。

## HBM 自动化与虚拟连接（0.1.6）

- **等离子锻炉**：原生物品端口可送入当前选定配方的原料，沿用原配方的槽位和物品验证；产物抽取保持原有行为，原料槽不能被当作产物抽走。图纸仍手动配置。
- **储罐与重型磁约束储罐**：沿用原端口与两组容器槽。满容器倒入罐中后输出空容器；空容器灌装后输出满容器。支持原生流体单元、通用流体罐、罐装容器，以及 NeoForge 流体物品接口接受的容器，保留各自流体类型和压力限制。物品管道实测接在核心位置正下方。
- **喷气背包**：按 HBM 原生燃料类型充填；未充满时保留在输入槽，只有充满后才转到输出槽。缺燃料时等待补充，输出被占用时等待空位，保留物品名称和组件。
- **虚拟连接断开器**：剪刀与红石粉无序合成，也可从 TECH 自动化创造物品栏取得。依次右键两座电线杆／输电塔，或两个管锚，删除两点之间的虚拟连接；端点方块及其他分支保留。再次点同一起点或潜行右键方块取消选择。跨维度、混合端点、无连接或起点未加载时给出提示；不会为找起点强加载区块。

实现固定针对当前 NTM `1.0.1+mc26.2`。容器接收判断使用容器副本和可回滚的嵌套事务，避免 HBM 原容器检测在 Pipez／AE2 的物品事务里再开根事务而报错。虚拟连接通过 HBM 原生图接口删除，立即同步两端显示并保存在原图数据中。

`python3 scripts/verify-hbm-automation.py` 使用已有 `runGuidanceClient` 的 MCPFabric 桥，只允许独立单人世界 `GuidanceVerification`。测试原料路由、错误物品拒绝、事务回滚、容器双向转换与物资守恒、背包等待／满输出、实际 Pipez 搬运，以及原生线缆卷／管道扳手创建连接后的指定分支删除。完成保存并重新载入该测试世界后，执行 `python3 scripts/verify-hbm-automation.py --saved` 验证断开的连接不复活、其他分支仍在。报告在忽略目录 `runs/evidence/hbm-automation-verification.json`；测试不连接生产服、不读取生产存档。

## 0.1.7 外壳自动化与 AE2 配方兼容

玩家在 0.1.6 上实测后确认，核心坐标能访问不代表多方块外壳可用。修正如下：

- 普通／重型磁约束储罐的原生流体接口外壳同时开放容器物品接口，沿用槽位及流体类型、模式限制；封闭面保持封闭。
- 等离子锻炉与聚变增殖仓补充对外流体槽枚举，沿用原生输入／输出角色及事务回滚。增殖仓外壳允许输入原生增殖配方材料；锻炉允许输入原生催化剂（含金-198），保留图纸与产物权限。
- AE2 对 NTM `StateShapedRecipe` 按真实宽高与空槽展开为九宫格；修正样板编码及 JEI 合成终端缺料位置映射。配方与组件匹配规则不变，AE2／JEI 缺失时跳过可选 Mixin。

`verify-hbm-feedback.py` 使用真实完整多方块外壳，运行原版漏斗和通电 AE2 导入／导出总线，核对容器灌装回收、流体双向传输、增殖仓及锻炉输入，并比较全部 NTM 有序配方的 AE2 九宫格结果。`verify-hbm-jei.py` 打开实际 AE2 终端和 JEI 页面，通过 Minecraft Automation 点击填充与编码按钮，在服务端检查配方匹配及样板解码；覆盖 NTM 1×3、2×2 和原版钻石斧。测试只允许隔离单人世界。

## 0.1.8 空储罐与存储总线

未预设流体的新储罐可以接收首种流体或满容器，空容器可以先排队等待流体。外部事务继续使用NTM原生共享journal，模拟／嵌套回滚不选择流体类型，提交后才由原生fill写入；保留模式、压力、已选类型和损坏限制。底部等已有开放流体面可由AE存储总线双向访问，流向仍受储罐模式限制。未扩大到原生封闭外壳。

`verify-untyped-tanks.py`验证全新罐、实际底部AE存储总线、首次灌装、混流拒绝和事务回滚；`verify-kerosene-hoppers.py`验证原端口真实漏斗灌装煤油通用流体罐、燃料罐和独立喷气背包。固定ID的`hbm:cell_empty`只支持NTM定义的满单元（例如氘），NTM未定义煤油单元，不能把它当通用煤油容器。粒子胶囊也不等同于普通流体容器；本版不新增通用单元或重注册原生物品。

## 0.1.9 改装胸甲自动充装

自动化输入与完成输出现在识别原生装甲附件。对物品／储罐副本调用NTM的`serveFillableMods`；独立可充装物品调用原生`loadTank/unloadTank`，不维护物品ID或燃料白名单。真实充装仍由储罐原生tick执行，模拟和输入判断不修改原物品。缺油时保留未满胸甲，原生规则判断不能继续充装后才进入输出槽；堵塞时等待，保留全部组件。

`verify-armor-tanks.py`用原生`ArmorModHandler.applyMod`制作喷气／缓降背包改装胸甲，覆盖两种储罐、真实漏斗和通电AE导入／导出、事务回滚、错误流体／压力拒绝、部分充装、输出堵塞、名称／耐久与其他附件保留。测试只在隔离世界执行。

## 假人网络缓冲释放（服务端 0.1.4）

SiliconeDolls 的普通发包会忽略客户端消息，但 HBM 直接写入底层 EmbeddedChannel，消息和引用计数缓冲会积压在没有消费者的出站队列。服务端 Mixin 仅将 FakeClientConnection 新建的通道替换为 ClientlessChannel：沿用原通道和写入成功语义，在 Netty 出站回调中立即消费并释放该回调拥有的引用，不改真人连接和 HBM 的共享消息所有权。

50 项服务端 JUnit 回归通过，其中 7 项覆盖真实假连接构造、10 万条 retainedDuplicate、ByteBufHolder／非引用消息、未 flush 关闭、普通 EmbeddedChannel 对照，以及真实 HBM 批处理和多接收者共享缓冲。`python3 scripts/verify-fake-network.py` 在独立 GuidanceVerification 世界验证 1 万次真实 HBM 发包后队列为空／引用归零、3 次原生假人加入和移除循环、真人客户端收到共享 HBM 包，以及清理测试假人；6 项通过。脚本不允许生产世界。

## 只读世界与 AE2 查询（服务端 0.1.1）

`techquery` 返回能力目录，`techquery <JSON>` 执行查询。需要管理员权限，通过既有 Minecraft 命令通道接入 AI，不需要升级客户端、MCSP/Nexus 或给 AI 挂载宿主目录。

提供 18 类数据查询：实时状态、地表/群系地图采样、已加载机器和实体搜索、普通方块暴力搜索、保存区块的方块搜索、容器与物品组件、方块/实体/command storage 的完整 NBT，以及世界目录内 `.dat` 与单个 Anvil 保存区块 NBT；AE2 可查询电力/频道、缓存库存、节点坐标、接口配置和存量、样板输入/输出/槽位/坐标、CPU 和合成任务。

- 只读，无物品存取、制作、改 NBT、生成/强加载区块。AE2 为可选依赖；缺少时通用查询可用，专用查询明确失败。
- 支持字段路径、多匹配选择、字段/值搜索、保留类型的 SNBT 和 Unicode 字符分页。数据截断、未知与失败单独标明，失败经标准命令错误回传，不把返回 0 当成成功。
- 地图扫描半径最多 256，普通方块扫描每次最多 32768 工作单位，按 cursor 续查；列表最多 64 项，输出最多 48 KiB。离线方块数据直接解码实际 Anvil 调色板，不维护世界索引。
- 存档读取限制在当前世界真实目录内的指定记录，不允许路径逃逸；压缩和解压分配均限制 8 MiB，支持 gzip/zlib/raw 及外部区块。带文件时间与记录 SHA256，读取变化时报错；磁盘数据可能落后于实时内存，且不是原子世界快照。
- 示例：`techquery {"query":"blocks.find","dimension":"minecraft:overworld","x":0,"y":64,"z":0,"radius":64,"min_y":-64,"max_y":128,"filter":"diamond_ore"}`。
- 示例：`techquery {"query":"ae2.patterns","dimension":"minecraft:overworld","x":0,"y":64,"z":0,"filter":"iron_plate"}`。

AI 使用说明由 infra-ops 的 `scripts/deploy/minecraft-hbm/ai-skills/tech-world-query/SKILL.md` 管理。运行中的独立测试客户端打开 GuidanceVerification 后，执行 `python3 scripts/verify-world-query.py`；无 AE2 降级实服验证执行 `python3 scripts/verify-query-no-ae2.py`。两者均只使用独立测试世界。
